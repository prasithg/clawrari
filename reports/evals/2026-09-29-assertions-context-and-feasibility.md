## Grader / Eval-Fault Check

These walkthroughs evaluate the decisions expressed by the prose. They do not demonstrate runtime enforcement. The deliberately violating fixture is an intentional control, so its expected failure must be inspected by reason as well as exit status. An unrelated crash would not validate the assertion.

For absence checks, an incorrectly forbidden identifier can block a valid suite; the maintainer pays the investigation cost. For context pruning, a relevance grader can undervalue implicit rules or misclassify session audiences. Preserve verifiable evidence and review those judgments before changing instructions. No new runtime check or alert is installed here.

## Lessons Learned

Exercise the failure an assertion promises to detect. Check data prerequisites before spending effort on an algorithm. Preserve important instructions when reducing startup context, and keep repository conventions discoverable from one maintained reference.
