Two Playbooks. One System.

The playbooks are what separate a working setup from a collection of config files.

Build Playbook

From Zero to Running

Step-by-step guide for bootstrapping a fresh OpenClaw install. Verified against a clean machine — every path, every config, every connector.

  • → Core file structure and workspace layout
  • → Memory system setup (daily logs + semantic search)
  • → Cron job scheduling for autonomous work
  • → Connector auth flows (Google, GitHub, Slack…)
  • → Night work queue and sub-agent orchestration
Model Playbook

Right Model, Right Prompt

Not all models respond to the same prompt structure. The model playbook routes tasks to the right model with the right prompt conventions.

  • → Routing table: task type → model family
  • → Per-family prompt conventions (Anthropic, OpenAI, Google, z.ai)
  • → Model overlays for main-session behavior tuning
  • → Cost-aware orchestration strategy
  • → Orchestration decision tree for complex work

Quick Start

# Clone it
git clone https://github.com/prasithg/clawrari.git
cd clawrari

# Run the bootstrap (~2 minutes)
./bootstrap/init.sh

# Follow the build playbook
open docs/playbook.md

# (Optional) Set up model playbook
open docs/model-playbook/README.md

Bootstrap generates core files. Playbook covers connectors, cron, night work, and upgrades.

Philosophy

Opinionated defaults. Not 47 options. THE setup, with rationale for every choice. Fork and customize from a known-good baseline.

Battle-tested. Everything here runs in production daily. If it's in Clawrari, it works. If it doesn't work, it's not in Clawrari.

Your AI should have a personality. Not a corporate drone. Not a sycophant. A sharp partner with opinions, humor, and honest feedback.

Memory is the foundation. An AI that forgets everything between sessions is just a search engine. Structured memory is what makes it a second brain.

Errors are bugs. If a cron job fails, that's not a footnote. That's something to fix now. Silence around failures is the enemy.
