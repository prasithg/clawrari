# avoid-ai-writing — AWDS (AI-Writing Defense System)

**Status:** v0.1
**Source of truth:** This skill is the single, canonical home for Clawrari's anti-AI-tell voice rules. This file + `patterns/` + `CHANGELOG.md` define the rules, scoring, and workflow. Every other voice/writing-style/persona/publish doc in this repo **defers to this skill and loses on any conflict.** Build your own rules from your own observations — synthesize from external work, but the patterns, scoring, and corpus are yours and evolve continuously.

## Purpose

Detect and rewrite AI-tells in your content before it ships. A simple "red-team" check looks at v1 vocabulary (em-dashes, hype words, emoji). That layer is necessary but not sufficient. The strongest fingerprints live at the **structural** layer: "Not X. Y." parallelism, uniform rhythm, "actual/real" intensifier inflation, manufactured generalizations. This skill catches those too.

This is a **system**, not a static skill: an autoresearch loop mines your own shipped/drafted output, finds new tells, and updates `patterns/v4-emerging.md` so detection keeps up with your own drift.

## When to use

Mandatory pre-ship gate for every piece of content a generation step produces (originals, replies, hooks). Mandatory pre-ship gate for any agent-generated text headed for an external surface or a human-review channel. The content engine's draft pipeline runs this gate before any preview is posted (see `docs/content-engine.md`).

## Workflow (the gate)

For every candidate piece:

1. **Detect mode** — score against all four pattern files. Output a `flags` array, a `categories` count, and a `verdict`:
   - **CLEAN** — 0 P0 flags AND 0 P1 flags AND ≤2 categories touched. Ship.
   - **PATCH** — 1-2 P0 flags OR 3-4 P1 flags OR 3-4 categories touched. Surgical edit, preserve intent.
   - **REWRITE** — 3+ P0 flags OR 5+ P1 flags OR 5+ categories touched OR uniform-rhythm fingerprint detected. Rewrite from scratch using the variance rules below.

2. **Variance rules (apply before re-scoring a rewrite):**
   - In a batch of 5 reply drafts, max 1 may use "Not X. Y." parallelism.
   - In a batch of 5 reply drafts, max 1 may close on a 1-4 word kicker fragment.
   - Hook block bullets must be full claims with verb + number, never bare noun phrases.
   - Strip all double-spaces after periods. Default to single-space.
   - Drop "actual/real" as voice intensifiers unless they create a real contrast.
   - At least 1 piece in 5 must open with something other than a data-density opener (vary: question, observation, callback, fragment).
   - Sentence rhythm must vary across the batch — not every piece can land on the data-opener -> short fragment -> mid-explainer -> kicker shape.

3. **Re-score** — if the rewrite still trips the REWRITE threshold, escalate. Do NOT ship a piece that fails the gate twice. Hold for human review.

4. **Log** — append every gate run to a corpus ledger (`corpus/flagged/<date>-<piece-id>.json`) with: original text, flags, verdict, rewrite (if any), final ship status. This becomes training data for autoresearch. The corpus is operator-local — treat it as append-only and keep it out of version control if it contains private drafts.

## Pattern files

- `patterns/v1-lexical.md` — banned vocab, em-dashes, hype words, emoji caps. Legacy v1 rules. Necessary, not sufficient.
- `patterns/v2-formatting.md` — double-spaces, hashtag rules, capitalization fingerprints, list shape rules, restricted-mrkdwn leakage.
- `patterns/v3-structural.md` — the layer that catches template drift. "Not X. Y." parallelism, uniform rhythm, "actual/real" inflation, manufactured "Most X are Y" generalizations, hollow short fragments as voice template, hot-take formula, bare-NP bullet lists, confidence-calibration weasels, manufactured-experience cadence.
- `patterns/v4-emerging.md` — autogenerated by the autoresearch loop. Patterns you caught yourself producing recently that don't fit v1-v3. This file evolves; the loop appends and a human prunes.

## Scoring rubric

Each pattern entry has:
- `id` — stable identifier (e.g. `v3.01-not-x-y`)
- `severity` — P0 (high-fingerprint) / P1 (likely tell) / P2 (judgment-call)
- `detect` — regex, keyword set, or structural rule
- `rewrite` — example of what to do instead

Verdict math: see step 1 of Workflow.

## Autoresearch loop (the system)

The skill is not static. On a weekly cadence, an **AWDS Pattern Research** job:

1. Pulls the last 7 days of your drafted + shipped output, performance rollups, and the corpus of what the gate already caught.
2. Cross-model analysis: spawns two reviewers from **different model families** in parallel. Each independently audits the corpus for tells the current `patterns/*` files DON'T catch. Different training priors catch different fingerprints.
3. Diff the two findings. Patterns both reviewers flag → strong candidates for v4. Patterns only one flags → weak candidates, log for human triage.
4. Append strong candidates to `patterns/v4-emerging.md` with: id, severity proposal, detect rule, rewrite example, source reviewer, week of detection.
5. Promote candidates from v4 to v3 after 2 consecutive weeks of recurring detection in the corpus (proves it's a recurring tell, not a one-off).
6. Write findings to an autoresearch log.
7. Append to `CHANGELOG.md`: weekly summary of new patterns, promotions, deprecations.
8. Alert only on the meaningful events (new promotions to v3).

This is the self-improving piece. The skill gets smarter every week without heavy human curation; humans only step in to prune false positives or veto promotions.

## Eval / regression tests

Maintain a growing set of known examples with expected verdicts. Before any pattern file change ships, run the detector against the eval set — it must stay green. New tests get added by:
- The autoresearch loop when it promotes a v4 → v3 pattern (auto-adds the original flagged piece as a test).
- Humans when they manually flag a piece the gate missed.

## Hard rules

- Never auto-ship REWRITE-verdict pieces. Always reroute to the rewrite path.
- Never use the gate as a vibe check — it's a structural detector. Vibe stays in the human review loop.
- Never edit the corpus ledger after the fact. Append-only.
- The skill is yours. Synthesize from external work; don't blindly import a third-party version and let it drift from your actual voice.
